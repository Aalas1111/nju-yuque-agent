## 2. 三条通用教训

1. **fake 要比被测代码更「不友好」。** Bug 6/7 都是「假件太善良」放过去的：
   测试把带标记的**原始** markdown 原样喂回去，而真语雀会把 HTML 标记剥掉；
   另一条干脆没测过 `dir_list`。凡是真实系统会做的规范化/裁剪，假件都得照做一遍。
2. **同一件事有多份实现，早晚有一份走偏。** Bug 9 就是：算「文档所在目录」曾有三份实现、两份是错的。
   现在只允许一条路（见 `tools._doc_dirs` 的注释）。
3. **契约与提示词之间的漂移不会报错**，只会静默地少发/多发消息（Bug 8）。
   这类只能靠守卫测试盯着：`tests/test_safety.py` 里那一组「文档漂移守卫」就是为它建的。

## 3. 噪声治理的实测数字（需求方报过的问题）

| 场景 | 治理前 | 治理后 |
|---|---|---|
| 「建空文档 → 改标题 → 写正文」（12 秒内 3 次变更） | 5+ 次 run（其中至少 4 次是噪声） | **1 次** |
| 程序写《工作日志》之后 | 每 ~37s 自激一次，**停不下来**（13 次 run 里 8 次是这个循环） | **不再触发** |
| 语雀刚建出来的「占位标题 + 空正文」文档 | 每次都唤醒 LLM | **不唤醒**（程序剔除）；标题一改就立刻失效 |

机制见 `docs/design.md` §8（静默期合并 / 忽略自己写的文档 / 占位标题过滤）。

## 4. 安全边界的实测结论

* 日常轮询的 session 里 `run_start.tools` **没有任何语雀写工具**；只有归档会话才挂上那 5 个。
* 给了删文档 / 移目录的能力之后，归档会话逐条核查、判定「已是目标形态」，
  **一次结构都没动**（`kb_writes == []`）。「给能力但不滥用」在这个案例上可观测。
* 但别把那次当成保证：同一轮它差点被 Bug 6 的假结果骗到——**能力边界才是闸门，模型的自律只是运气**。
